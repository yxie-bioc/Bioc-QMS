# BBC 网站：Windows 快速开始

目标：Windows 10 22H2 / Windows 11 x64。自动验收使用 Windows Server 2022 x64；你的具体 Windows 版本、公司网络和另一台实体电脑仍须在本机验收。业务网站是普通浏览器网站，不需要每位同事安装客户端。

## 先在自己的电脑试用

1. 下载 **BBC-QMS-Windows-x64.zip**，右键“全部解压”。建议使用短路径，例如 `C:\BBC-QMS\0.2.0`，或个人有写入权限的目录。不要在 ZIP 内直接运行，也不要使用 GitHub 的“Source code”ZIP。
2. 双击 **启动网站.cmd**。普通 Chrome / Edge 会打开中文运行管理页。
3. 第一次选择“合成测试”，点击“建立实例并启动”。在“查看合成测试账号”中取得各自随机生成的邮箱和密码，然后点击“打开业务网站”。
4. 先用 owner 账号起草文件；独立评审、批准、培训、QA 生效需要换用不同账号。样例记录与规则均为测试用途。

不需要安装 Node、数据库、npm、Git、Docker 或 WSL。若主机缺少 Microsoft Visual C++ 运行库，先双击 **准备Windows运行环境.cmd**。它直接从微软下载固定文件、核对 SHA-256 与微软签名，再打开微软安装向导。此一步需要联网，且可能要求管理员授权；日常启动不需要联网下载。不要关闭安全保护或跳过证书警告。

## 日常使用

- **启动／打开**：双击“启动网站”；重复双击会复用同一管理进程。
- **停止**：管理页点击“停止网站、提醒和数据库”，或双击“停止网站.cmd”。关闭浏览器不会停止后台服务。
- **状态与错误**：管理页分别显示网站、worker、数据库和最近提醒运行。页面下方可以查看诊断信息；启动失败的命令窗口会保留错误，不会直接消失。
- **完整备份**：点击“立即完整备份”。管理页显示备份位置及最近成功／失败时间。可把位置改到受控外接盘或备份位置；不会自动安装备份计划。
- **恢复**：选择完整备份文件夹，输入一个新实例名称，例如 `restore-2026-11`，点击“恢复为新实例”。核对成功后切换到新实例，启动并登录检查。不会覆盖旧数据。使用与备份对应的原运行包恢复，再升级。
- **更新**：新版本解压到另一个目录，保留旧包，双击新包“启动网站”。程序会停止旧服务，做升级前备份和独立恢复核对，再迁移。失败时不会开放网站。不要把旧程序覆盖进新程序目录；数据库回退必须使用升级前备份和匹配版本恢复到新实例。

数据默认放在当前 Windows 用户的 `%LOCALAPPDATA%\BBC-QMS`。管理页会显示完整路径。程序、实例数据库、附件、凭证、日志和备份各自分开。中文路径会自动使用当前用户专用的 PostgreSQL 兼容目录入口，实际数据仍在原目录；若公司策略禁止创建该入口，错误信息会显示需要 IT 授权的具体目录。不要删除数据目录，不要把它上传 GitHub，不要复制正在运行的数据库文件夹当作备份。

## 公司内网共享

1. 指定一台持续开机、联网且不休眠的主机，并用同一个 Windows 主机账号管理它。公司应指定备份及故障处理负责人。
2. 测试时，可在管理页选择“内网 HTTP 合成数据试验”，选当前内网地址和端口。该模式仅允许合成测试实例。
3. 真实使用的空实例请选择“内网 HTTPS”。由 IT 准备固定内网 IP 或内部 DNS 名称、匹配名称的 PEM 证书链及私钥，并在员工电脑部署公司证书信任。管理页填写完整路径与访问网址。
4. IT 明确批准后，只为所选网站端口和公司子网开放 Windows 防火墙。无需开放数据库端口；此工具不会自动改防火墙、导入根证书、添加系统服务或自启动。
5. 把管理页显示的**业务网站网址**发给同事，为每人创建独立账号并按职责配置角色和范围。不要把本机管理地址、测试密码、整个数据目录发给同事。
6. 至少从另一台真实电脑登录、上传和下载附件，并验证退出、权限与证书无警告。多浏览器上下文测试不等于已完成这项公司网络验收。

从测试转到实际使用：新建 `company` 等独立空实例，设置自己的技术管理员。它没有测试账号或示例业务记录，管理员也没有自动的业务批准资格。实际审批规则、参考数据、库存权威来源和保留政策仍需要确认。

## 常见问题

- **端口已占用**：在管理页换一个网站端口；不要手工结束不认识的进程。
- **电脑换了网络后同事打不开**：管理页重新选择当前内网地址；长期共享让 IT 配置固定 IP / 内部 DNS。
- **HTTPS 证书报错**：让 IT 核对主机名、有效期和员工电脑的信任链。不要点击忽略警告。
- **异常关机后启动失败**：保留日志、实例目录与备份。重新启动会由 PostgreSQL 自行恢复；不要删除 `postmaster.pid` 或修改数据库文件。
- **没有管理员密码**：测试实例可在本机管理页查看随机测试密码；空实例使用你首次设置的密码。目前没有邮件找回或公司 SSO，必要时交由受控维护处理。
- **关闭主机后收不到提醒**：主机停止时服务与提醒均停止，这是预期行为；运行时提醒由独立 worker 处理，当前仅站内通知。
